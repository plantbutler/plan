Ranking picked on 2026-09-03, to be re-probed before "What does this plant want?" is built, because
this corner of the web goes offline quietly.

**Perenual first.** Houseplant- and garden-facing, and its vocabulary is regimes — watering
Frequent/Average/Minimum, a watering benchmark in days, a sunlight array, hardiness, an indoor flag.
That is the right shape precisely because it does not pretend to publish soil-moisture percentages.
Free key, daily request cap.

**Trefle second.** Numerically richer — light and atmospheric humidity on 0-10 scales, minimum and
maximum temperature, soil texture, pH — but biased toward crops and wild species, so houseplant
coverage is patchier, and the hosted API's uptime is the open question. A self-hosted dump is the
backstop if it is gone.

**OpenFarm dropped.** Crops, sparse, nothing a flat contains.

**GBIF or POWO are not care sources and are not ranked with them.** They carry taxonomy only, and
their job is one hop before the care query: resolve "monstera", or a typo, to an accepted binomial so
the cache key is stable. Without that hop every misspelling mints its own junk row.

Only one source answers per plant, recorded with its fetch date. Mixing or averaging two sources
that disagree produces a number neither of them stands behind.

## Re-probed 2026-09-03

The note asked to be re-probed before the pitch is built, because this corner of the web goes
offline quietly. It does.

- **Perenual** answers. `GET /api/species-list` returns
  `{"message":"Missing/Issue with API Key..."}` to a bad key — an odd status code for it, but the
  endpoint is there and rejecting properly. There is no `/api/v2`. Needs a free key.
- **Trefle** answers: `{"error":true,"messages":"Invalid access token"}`. The hosted API is up
  today, which was the open question. Needs a token.
- **OpenFarm is gone**, not merely sparse: `openfarm.cc/api/v1/...` now redirects to its GitHub
  repository. Dropping it was right and is no longer a judgement call.
- **GBIF** answers with no key at all, and does the job asked of it:
  `species/match?name=monstera deliciosa` returns `Monstera deliciosa Liebm.`, matchType EXACT,
  confidence 99, status ACCEPTED. The taxonomy hop is free and works.

**What this changes.** Both ranked care sources need an API key, and keys are secrets that never
enter a repository — so they live in `deploy.env` beside the butler's token, and the pitch cannot
be finished until Jacopo has signed up for at least one. Everything else in it can be built
without one: the taxonomy hop, the cache table, the regime-to-band mapping and the type-it-in
fallback. With no key configured the lookup simply fails, which is the path the pitch already
requires to work.

## Probed with real keys, 2026-09-04 — the ranking is overturned

Jacopo supplied free keys for both. Neither free tier provides what the pitch is built on.

**Perenual free is names only.** `species-list` returns the species and their binomials, but every
care field — `cycle`, `watering`, `sunlight` — is replaced verbatim by
`"Upgrade Plans To Premium/Supreme - ... I'm sorry"`. `species/details/{id}` and
`species-care-guide-list` both answer HTTP 429 `"Please Upgrade Plan"`. The watering regime and the
benchmark-in-days that put Perenual first are behind a paid plan; the free key cannot reach them.

**Trefle free returns real data, but not the field that matters.** Fifteen species pulled
individually off one page of `/species`:

| field | filled |
| --- | --- |
| `light` | 11/15 |
| `atmospheric_humidity` | 11/15 |
| `ph_minimum` | 11/15 |
| **`soil_humidity`** | **0/15** |
| `soil_texture` | 0/15 |
| `minimum_temperature` | 0/15 |

`soil_humidity` is the one field that could drive a watering band, and it is not populated at all —
absent, not patchy. And the houseplant bias is worse than "patchier": `Monstera deliciosa`,
`Dracaena trifasciata`, `Spathiphyllum wallisii` and `Chlorophytum comosum` all exist with every
growth field null, and `Ficus lyrata` is not in the database. The species that do carry data are
crops: tomato and basil have light, humidity and pH.

**GBIF stands.** Free, no key, and it does its job.

### What this means for the pitch

There is no free watering regime to map onto a target band, which is the pitch's central
mechanism. Three honest ways forward, and the choice is Jacopo's:

1. **Pay Perenual.** It is the only source that publishes a watering regime and a benchmark in
   days. The pitch then works as shaped.
2. **Keep the lookup, drop the watering half.** Trefle for light and humidity as context for the
   sunlight-hours ambition; the target band comes from a local table over soil, pot size and plant
   type, which the pitch's own no-go already says the numbers must be.
3. **Species as a label only.** GBIF normalises the name so the field is clean and the cache key
   is stable; every care number is typed in. Cheapest, and honest about what is knowable for free.

The ranking, as it now stands for a free key: **Trefle first** — it is the only one that answers
with care data at all — **Perenual second and unusable** until somebody pays. That is the reverse
of the order picked on 2026-09-03, and it was picked from documentation rather than from answers.

Follows from the note "Plant care data, Planta-style", which is where the ambition and the
verdict-log dataset are written down.
